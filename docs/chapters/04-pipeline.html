第三章 基础范式：单任务因果推断的标准调度流

3.1 Prompt 六要素结构

一条能进论文的调度指令，必须含六要素。少一个，结果就要返工。

要素 作用 反例 正例片段
① 角色与目标 锚定任务性质 “帮我跑个回归” “以实证研究助理身份，完成基准 DID 估计”
② 数据与样本 消除歧义 “用面板数据” “使用 01_raw/city_panel_v3.dta，样本限定 2008–2022、剔除缺失被解释变量”
③ 命令与设定 保证可比 “跑 DID” “reghdfe y did, absorb(city year) cluster(city)，另用 csdid 做交错稳健对照”
④ 输出规格 决定能否交付 “给我结果” “输出 esttab 三线表（系数/se/星号/N/R²）、事件研究图 png、完整 log”
⑤ 校验要求 决定可信度 无 “报告处理组/对照组样本量、平行趋势检验统计量、VIF”
⑥ 留存要求 决定可复现 无 “do 存为 02_do/b01_baseline_v1.do，log 同名，写入多维表格一行”

六要素口诀（板书）：谁做、用什么做、怎么做、交什么、怎么验、存哪。

3.2 DID 全流程示例（基准 → 事件研究 → 表格）

Step 1 基准估计

* b01_baseline_v1.do  —— 基准双向固定效应 DID
version 18
clear all
set more off
set seed 20261108

use "01_raw/city_panel_v3.dta", clear

* 样本规则（写死在 do 里，不靠提示词）
keep if year >= 2008 & year <= 2022
drop if missing(y)
xtset city year

* 基准
reghdfe y did, absorb(city year) cluster(city) keepsamplealways
estimates store m1

* 加控制变量
reghdfe y did $controls, absorb(city year) cluster(city)
estimates store m2

* 交错处理稳健对照
csdid y $controls, ivar(city) time(year) gvar(first_treat) method(dripw)
estimates store m3

esttab m1 m2 using "05_delivery/tab_baseline.rtf", replace ///
    b(3) se(3) star(* 0.10 ** 0.05 *** 0.01) ///
    stats(N r2_a, labels("N" "Adj. R2")) ///
    title("表1 基准回归结果")

log using "03_log/b01_baseline_v1.log", replace text

Step 2 事件研究（平行趋势）

* b02_event_v1.do
use "01_raw/city_panel_v3.dta", clear
keep if inrange(year,2008,2022)
xtset city year

* 生成相对时间虚拟变量（以 -1 期为基期）
gen rel = year - first_treat
forvalues k = 5(-1)2 {
    gen pre`k' = (rel == -`k')
}
forvalues k = 0/4 {
    gen post`k' = (rel == `k')
}
* 基期 pre1 省略

reghdfe y pre5 pre4 pre3 pre2 post0 post1 post2 post3 post4 $controls, ///
    absorb(city year) cluster(city)

coefplot, keep(pre5 pre4 pre3 pre2 post0 post1 post2 post3 post4) ///
    vertical yline(0) xline(0) ///
    coeflabels(pre5 "-5" pre4 "-4" pre3 "-3" pre2 "-2" ///
               post0 "0" post1 "1" post2 "2" post3 "3" post4 "4") ///
    xtitle("相对政策实施期") ytitle("处理效应") ///
    title("图1 事件研究：平行趋势与动态效应")
graph export "04_figure/fig_event_study.png", replace width(2000)

关键教学点：事件研究的基期选择与端点期合并（把 -5 以前合并为 pre5、+4 以后合并为 post4）是审稿人最爱挑的点。要求在 Prompt 里显式写死这两条，否则 AI 常默认做”每一期一个虚拟变量”，导致共线性或样本稀疏。

Step 3 表格与图回流

  • esttab 输出 rtf/tex → 上传云盘 → 贴入飞书文档《回归表模板》

  • png → 上传 04_figure → 飞书文档插入

  • 一行记录写入多维表格：项目ID、批次号、子任务名、方法、系数、se、p、N、R²、do链接、log链接、图链接、状态

3.3 RDD 全流程示例

* b03_rdd_v1.do
use "01_raw/score_panel.dta", clear

* 1) 断点有效性：密度检验（操纵检验）
rddensity running, c(0) plot

* 2) 带宽选择 + 稳健估计
rdrobust y running, c(0) all
estimates store rd_main

* 3) 协变量平衡（断点两侧）
rdrobust x1 running, c(0)
rdrobust x2 running, c(0)

* 4) 带宽敏感性
foreach h in 0.5 0.75 1 1.25 1.5 {
    rdrobust y running, c(0) h(`h')
}

* 5) 安慰剂断点
foreach c in -0.2 -0.1 0.1 0.2 {
    rdrobust y running, c(`c')
}

AI 常错点（必须写进 Prompt 校验项）：

  • 忘记 rdrobust 默认已是稳健偏差校正，又手动加上传统方差 → 重复

  • 混淆 h（带宽）与 b（bias band）参数含义

  • 密度检验仅做图不做统计量（应报告 p 值）

  • 平衡性检验只用均值差，不做断点邻域内检验

3.4 PSM / PSM-DID 全流程示例

* b04_psm_v1.do
use "01_raw/firm_panel.dta", clear

set seed 20261108
set matsize 2000

* 1) 倾向得分
psmatch2 treat $xlist, outcome(y) logit neighbor(1) common cal(0.01) //
    ties noreplacement

* 2) 平衡性检验（必须报告标准化偏差）
pstest $xlist, both graph
graph export "04_figure/fig_psm_balance.png", replace

* 3) 共同支撑
psgraph

* 4) PSM-DID
* 用 _weight 加权的 DID
reghdfe y did [aw=_weight], absorb(firm year) cluster(firm)

教学要点：PSM 的”结果好不好”不看 ATT 显著不显著，看平衡性。要求 Prompt 强制输出 pstest 的标准化偏差表与共同支撑图，否则交付不合格。

3.5 结果回流飞书的三种方式

方式 适用 做法 优点 风险
A 表格直写 结构化数值（系数、p、N） MCP 返回结构化字段 → 连接器写多维表格行 可筛选、可看板、可统计 字段映射错会静默丢数据
B 文档嵌入 成品表格与图 产物上传云盘 → 文档引用 直接可写进论文 版本多时易混乱，必须带批次号
C 双写（推荐） 交付批次 A 写台账 + B 出报告 台账可统计、报告可交付 需保证两者同源（同一 log）

规矩：台账必须与 log 同源。禁止”表格里手填一个更好看的 p 值”。这是第七章红线的技术落点。

3.6 结果自检清单（12 项）

交付前逐条打勾，任何一项不过，不得进入下一批：

  1. log 中无 r(####) 错误码

  2. 样本量 N 与基准一致（或差异有明确规则解释）

  3. 处理组/对照组样本数已报告

  4. 固定效应维度与聚类层级一致（聚类层级 ≥ 处理层级）

  5. 系数符号与研究假设方向一致（不一致必须解释而非隐藏）

  6. 标准误未异常缩小（警惕聚类错误或权重误用）

  7. 星号规则与表注一致（10%/5%/1%）

  8. 事件研究基期明确、端点合并规则写明

  9. 平衡性/密度/平行趋势检验已做且报告统计量

  10. 图文件名与批次号匹配，可反查 do

  11. do 文件含 set seed（涉及随机过程时必须）

  12. 多维表格行已写入且字段无空值

3.7 本章实操任务

用 sysuse 或课程提供的城市面板，完成：

  1. 一条基准 DID（含聚类）

  2. 一张事件研究图

  3. 一张 esttab 三线表

  4. 一行多维表格记录

  5. 提交：do 链接 + log 链接 + 图 + 表行截图

第四章 核心王牌：组织智能体并行委派流水线

全课重心。前三章解决”会不会跑”，本章解决”跑得多、跑得稳、跑得可核验”。这一章也是与 TraeWork / DSH 分野最明显的地方。

4.1 任务依赖图（DAG）判定法

并行度不是拍脑袋，是画图。把研究任务画成有向图，没有箭头相连的节点才能并行。

数据获取 → 清洗 → 变量构造 → 描述统计 → 基准设定
                                              ↓
                        ┌─────────────────────┼─────────────────────┐
                     安慰剂组              稳健性组              异质性组
                   （可并行 5–20 个）    （可并行 8–15 个）     （可并行 6–12 个）
                        └─────────────────────┼─────────────────────┘
                                              ↓
                                     汇总校验 → 诊断报告 → 评审

判定的三个硬问题（逐个问，任一为”是”就不能并行）

  1. 子任务 B 的输入是否依赖子任务 A 的输出？（是 → 串行）

  2. 两个子任务是否写同一个文件/同一行表格？（是 → 必须隔离目录或串行）

  3. 两个子任务是否需要同一随机种子的连续序列？（是 → 串行或显式分配独立种子）

4.2 可并行 / 必须串行 对照表

任务类型 可否并行 原因
不同安慰剂设定（时点前移、伪处理组、随机分配） ✅ 各自独立估计，互不依赖
不同带宽 / 不同核函数 / 不同多项式阶数 ✅ 参数扫描，彼此独立
分组异质性（东中西、国企民企、大小企业） ✅ 子样本独立
空间权重矩阵多设定 ✅ 各自独立估计
置换检验 N 次 ✅（分批） 每次独立；注意种子分配
替换被解释变量/解释变量口径 ✅ 独立重估
缩尾/截尾不同阈值 ✅ 独立重估
数据清洗 → 基准回归 ❌ 后者依赖前者产物
基准回归 → 确定最优带宽 半串行 需先看基准再定扫描范围
汇总矩阵 → 诊断报告 ❌ 后者聚合前者
多篇文献复刻 ✅（文献间） 各自数据与代码独立

4.3 批次设计四步法

Step 1 定锚：确定基准spec（样本、变量、固定效应、聚类、权重）。基准只有一个，且必须先单独跑通并人工确认。基准不稳，后面全废。

Step 2 列质疑：把审稿人可能提的质疑逐条写成任务。来自四个维度：

  • 时点：政策时点是否准确、是否存在预期效应、是否存在滞后效应

  • 样本：极端样本、特殊地区、样本选择、缺失机制

  • 设定：控制变量集、固定效应层级、聚类层级、权重

  • 测量：变量口径替换、测量误差、代理变量 每个维度产出 2–5 个任务，一批控制在 8–20 个（太少不值得并行，太多交付校验成本上升）。

Step 3 造清单：写成结构化任务表（见 4.4 模板）。每个任务必须独立可跑：独立数据读取、独立 do、独立 log、独立图名。

Step 4 定验收：批次执行前先写”什么算通过”。示例：基准系数 0.12（p<0.01）；通过标准 = 至少 80% 的稳健性检验符号一致且 p<0.10；任何检验出现符号反转必须单列说明。

4.4 并行委派 Prompt 标准模板

【任务类型】批量稳健性检验（并行委派批次）

【背景】
研究问题：X 政策对 Y 的影响
基准设定：reghdfe y did, absorb(city year) cluster(city)，样本 2008–2022，N=样本量
基准结果：系数 β=【填写】，se=【填写】，p=【填写】
数据文件：01_raw/city_panel_v3.dta（只读，不得修改）

【委派要求】
请将下列子任务委派给后台智能体并行执行。各子任务之间无数据依赖，必须彼此隔离：
- 每个子任务使用独立工作目录 05_delivery/batch01/{task_id}/
- 每个子任务输出独立 do、log、figure，命名含 task_id
- 全部子任务完成后统一交付，并做交叉校验

【子任务清单】
T01 基准复现（仅用于对齐，不作结论）
T02 安慰剂：政策时点整体前移 2 年
T03 安慰剂：随机抽取 300 个伪处理组（seed=20261108，并行时按 T03_1..T03_6 分配独立种子）
T04 稳健性：剔除直辖市与计划单列市
T05 稳健性：替换被解释变量为 y_alt
T06 稳健性：控制变量增减（加/减各一版）
T07 异质性：按东部/中部/西部分组
T08 异质性：按企业规模中位数分组
T09 敏感性：缩尾 1% / 5%
T10 敏感性：聚类层级改为省份

【每个子任务的输出规格】
1) do 文件（含 set seed、样本规则、完整命令）
2) log（完整，含错误码检查）
3) 若涉及图形：png 到 04_figure/batch01/
4) 一行结果记录：task_id、方法、系数、se、p、N、R²、结论方向（一致/反转/不显著）

【校验要求】
- 报告每个任务的 N 与基准 N 的差异及原因
- 标记所有符号反转或显著性下降的任务，不得省略
- 生成一张汇总矩阵（行=子任务，列=系数、se、p、显著性、方向）
- 若任一子任务失败，返回该任务的错误码与 log 片段，不影响其他任务交付

【交付】
- 汇总矩阵写入飞书多维表格《实证结果中台》，批次号 batch01
- 诊断报告写入飞书文档，含"结论稳定性判定"段落
- 明确告知：本批次交付完成后我才可发起下一批委派

模板使用要点（讲给学员的话）

  • 第 3 段”隔离”是防并发覆盖的关键，删掉它事故率会飙升

  • “结论方向”字段是防”只报显著”的技术手段

  • 最后一句是主动声明调度约束，避免学员以为 Agent 能连续接活

4.5 交付包目录规范与汇总矩阵

单批次目录树

05_delivery/batch01/
  batch_manifest.json          # 批次元信息：任务清单、开始/结束时间、环境版本
  summary_matrix.csv           # 汇总矩阵
  T01/{run.do, run.log, result.json}
  T02/...
  T03_1/ ... T03_6/            # 置换类可再分子批
  figures/                     # 该批次所有图
  failures/                    # 失败任务与 log 片段

batch_manifest.json** 最小字段**

  "data_file": "01_raw/city_panel_v3.dta",
  "data_hash": "sha256:xxxx",
  "stata_version": "18.5",

4.6 容错、重跑与失败归档

四类失败与处置

失败类型 表现 处置
环境类 包缺失、路径不存在 修正环境后重跑该任务，不动其他
语法类 r(198) 等 从 log 定位行号，改 do 重跑
数据类 子样本为空、共线 记录为”不可估计”，写入失败表并说明原因
超时类 置换/自助超时 拆小批次、降重复次数、提超时

原则：失败必须进交付包，不能静默消失。失败任务写进 failures/ 与汇总矩阵的”备注”列，评审时一并呈现。学术上，“这条做不了”本身就是信息。

重跑规范：重跑不改文件名，改版本后缀：T02_v2.do。原版保留。禁止覆盖。

4.7 调度约束下的三种分批策略

约束复述：同一对话内，上一批委派未全部交付核验前，不能发起新一批。

策略 做法 适用 代价
S1 单批大规模 一次塞 15–20 个任务 任务同质（如全部置换） 单点失败影响整批交付时间
S2 多对话分区 按主题拆到不同对话（识别稳健性 / 异质性 / 敏感性各一对话） 任务异质、想边跑边讨论 需人工合并各对话交付包
S3 串批流水 批1 交付 → 评审 → 批2 需要导师逐批把关 总时长最长，但质量最高

推荐组合：教学期用 S3（强调评审节奏）；项目冲刺用 S1+S2（强调吞吐）。永远不要为了并行而把”基准设定”和”稳健性”塞进同一批——基准没定，稳健性检验没有意义。

4.8 四大前沿场景（含实现要点）

场景 A：大规模置换检验并行

目标：给 DID/SCM 的估计量构造经验分布，得到更严格的 p 值。

实现要点

  1. 置换单元选择：处理分配层级（城市/省份）而非观测层级。选错会让 p 值虚低。

  2. 种子分配：seed = base_seed + 子批索引，写进 manifest，保证可复现。

  3. 并行切分：300 次 → 6 个子任务 × 50 次，每子任务落 placebo_XXX.csv。

  4. 合并：汇总所有”伪系数”，计算 p = (#{|β_placebo| ≥ |β_true|}+1)/(M+1)。这个 +1 很多 AI 会漏，必须在 Prompt 里写死。

  5. 出图：置换分布直方图 + 真实系数竖线 + 置信区间。

教学价值：这是最能体现并行收益的场景——串行 300 次可能 2 小时，并行 6 路约 20–30 分钟。

场景 B：异质性扫描

目标：一次性扫出”在哪些子群体里效应更强”，避免人工一个个写循环。

实现要点

  1. 分组维度表：地区、行业、企业规模、所有制、人口密度、财政能力等，每维 2–4 组。

  2. 每组独立子任务，输出组内系数、组间差异检验（suest 或交互项）。

  3. 汇总成热力图：行=维度，列=组，色=系数大小/显著性。

  4. 纪律：异质性扫描属于探索性分析，必须标注”探索性”，不能与预注册假设混为一谈（呼应第七章）。

场景 C：敏感性曲线

目标：证明结论不依赖特定参数设定。

实现要点

  1. 扫描维度：带宽（RDD）、缩尾阈值、控制变量集、固定效应层级、聚类层级、权重。

  2. 每个取值一个子任务，输出 (设定值, 系数, 置信区间)。

  3. 绘”系数—设定”敏感性曲线，附”结论翻转临界点”标注。

  4. 交付时明确：哪个设定下结论不成立，这是最有价值的发现，不是污点。

场景 D：空间权重矩阵与空间计量

目标：检验空间计量结论对权重矩阵设定的稳健性。

实现要点

  1. 权重矩阵集：邻接（0/1）、地理距离反比、经济距离、嵌套权重。

  2. 每矩阵独立跑 xsmle（SAR/SEM/SDM 各一版）→ 任务数 = 矩阵数 × 模型数。

  3. 汇总：直接效应/间接效应分解表（空间模型必须报告分解，不能只报总系数）。

  4. 注意：spmat 构建矩阵是前置串行步骤，必须先单独跑通并把矩阵存成文件，再并行估计。

  2. 设计一批 10 个子任务（含 1 个基准对齐任务）

第五章 前沿方法矩阵：把顶刊方法接进流水线

本章不重讲方法原理（那是计量课的事），只讲如何把方法接进并行流水线，以及 AI 在这些方法上最常犯的错。

5.1 交错 DID 与异质性处理效应

命令 用途 接入要点 AI 常见错
csdid Callaway–Sant’Anna 组别—时期 ATT 必须给 gvar（首次处理期，未处理设为 0 或缺失）；method(dripw) 与 method(dr) 结果常不同，必须都报 把 gvar 填成”是否处理”的 0/1
drdid 双重稳健 DID 需 ivar time treatment 三要素清晰 混淆面板与重复截面语法
did_imputation Borusyak 等插补估计 需完整面板，缺失处理需说明 面板不平衡未处理
eventdd 事件研究图 + 同步置信带 可配 accum 累积效应 基期未指定导致共线
did_multiplegt_dyn 多期/多组异质稳健 需 placebo 与 controls 参数 忽略其”动态效应”含义，仍按静态解读
alldid 多估计量对照集合 适合作为”一个任务=多方法对照”的聚合任务 只看其中一个估计量就下结论

流水线接法：把”同一数据的 4 种 DID 估计量”做成一个子任务（内部串行、对外并行），输出”多估计量对照表”。这比拆成 4 个子任务更有解释力，也更省交付成本。

教学金句：交错 DID 的稳健性不在于”换一个命令”,而在于同时报告多个估计量并解释差异。

5.2 合成控制与合成 DID

命令 用途 要点
synth 单处理单元 SCM 需 predictor 与 donor pool；trunit/trperiod 明确
synth_runner SCM + 安慰剂空间 + 前处理 RMSPE 一次出置换推断，批量并行的最佳载体
sdid 合成 DID（Arkhangelsky 等） 需平衡面板；权重与单位权重可输出

并行设计：synth_runner 自带 placebo 循环，可作为单任务；若处理单元多（多省政策），则”每省一个任务”并行，最后汇总”处理效应分布”。

AI 常见错：donor pool 污染（把受政策影响的其他单元放进对照池）；前处理拟合期太短；RMSPE 比值不报告。

5.3 模糊/分位数 RDD 与门槛回归

方法 命令 要点
模糊 RDD rdrobust + iv 思路，或 ivregress 局部样本 需报告第一阶段强度（弱工具问题）
分位数 RDD qrd 类命令（外部包）或分位数切分近似 分位数结果必须报多条分位线，不能只挑中位数
面板门槛 xthreg 需 rx() qx() thx() 明确；门槛个数用 bootstrap
密度操纵检验 rddensity 必做，报告 p 值与图

流水线接法：门槛回归的”门槛个数 + 门槛值 + 置信区间”三件套必须一起交付；分位数 RDD 建议做成”分位扫描”子任务集（0.25/0.5/0.75/0.9 各一任务）。

5.4 空间计量与空间 DID

命令 用途 要点
spmat 构建空间权重矩阵 前置串行；矩阵存文件复用
xsmle SAR/SEM/SDM 面板估计 需 wmat()、model()、fe/re 明确
spregress / spxtregress 官方 sp 系列 与 xsmle 结果口径不同，别混用
空间 DID 交互项 + 空间滞后 需同时报直接效应与间接效应

必须报告：效应分解（直接/间接/总）。只报总系数是空间计量最常见的外行错误。

5.5 机器学习因果：DML、因果森林、政策学习

方法 Stata 路径 要点
双重机器学习 ddml（SSC） 需 3 个 learner（如 reg + lasso + rf），样本分割次数、交叉拟合折数必须写死
堆叠/集成 pystacked 依赖 Python；需在 ENV.md 记录 Python 包版本
LASSO 变量选择 lassopack（lasso2/rlasso） 仅作选择，后续推断需正交化或 Post-double-selection
因果森林 Stata 内嵌 Python 调 grf 输出 CATE 分布 + 分组异质性 + 校准检验
政策学习 同上 + 自定义策略评价 需明确”政策价值函数”定义

并行设计：DML 的”不同 learner 组合”天然可并行（每组合一任务），输出对照表：ATE 估计的稳定性。这比调参追显著性更有学术价值。

AI 常见错：把 DML 当”高级 OLS”直接报系数不做稳健性；不报告 learner 设定；不检查重叠性（overlap）。

5.6 动态效应：PVAR、局部投影

方法 命令 要点
PVAR pvar 需 lags()、inst()（GMM）、Helmholtz–Hoffmann 变换
局部投影 lpirfs 类外部包 需明确 horizon、控制基期、聚类
脉冲响应图 pvarirf / irf 必须带置信带

流水线接法：PVAR 的”滞后阶数选择”（AIC/BIC/HQIC 三准则）可做成并行任务，输出阶数敏感性对照。

5.7 Stata × Python 混合执行

为什么需要：Stata 强在估计与面板处理，Python 强在置换分布、机器学习、可视化与批量 IO。

三种混合形态

形态 做法 适用
Stata 调 Python python script.py / python: 块 生成图、跑 sklearn
Python 调 Stata pystata（stata.run()） Python 编排、Stata 计算
MCP 分别调 两个工具并列，各跑各的 最稳，适合并行流水线

推荐第三种：并行场景下，让 Stata 任务与 Python 任务互不内嵌，各自独立进程，避免版本/路径互扰。混合内嵌只在单机探索时用。

5.8 方法—数据—样本量适配表

方法 最低样本结构 常见失败点 建议批次规模
双向 FE DID 面板 ≥ 5 期，处理组 ≥ 30 单元 聚类层级过低 8–12 任务
交错 DID (csdid) 多处理时点，每组 ≥ 2 单元 gvar 构造错 6–10

6.2 版本治理与命名规范

命名公式：{批次}_{任务}_{内容}_v{版本}.{ext} 示例：b01_T04_drop_municipality_v2.do

版本规则

  • v1 首次执行；v2 因评审修改；v3 因数据更新

  • 禁止 final、final2、最终版、真的最终 —— 这类命名是证据链的天敌

为什么这么严：论文返修时最常见的灾难是”我改了一版，旧结果找不到了”。多维表格天然保留全部历史，这是它相对文件夹管理的核心优势。

第七章 学术伦理、可复现性与风险边界

7.1 五条学术红线

  1. AI 产出必须人工复核。所有进入论文的数字，作者必须亲自核对 log。署名意味着责任，AI 不能署名。

  2. 不得选择性报告。所有跑过的检验（含失败、含反转）必须在台账留痕；论文可以只报部分，但台账必须全。

  3. 不得为显著性反复改设定。设定修改必须留版本号与理由；“试了 30 个设定取最好的”属于 p-hacking。

  4. 不得隐藏样本修改。样本筛选规则写死在 do 里，不得在结果出来后偷偷剔除。

  5. 不得把探索性分析包装成预注册假设。异质性扫描结果必须标注”探索性”。

7.2 可复现性八件套

# 内容 落地方式
1 do 文件完整可跑 从原始数据到最终表的单一入口 master.do
2 种子固定 所有随机过程 set seed，写进 manifest
3 包版本记录 ENV.md 记录每个外部命令版本
4 数据哈希 sha256 写入 manifest 与多维表格
5 样本规则前置 所有 keep/drop 集中在 do 前部，不散落
6 log 全留 每任务一 log，命名与 do 对应
7 表图可再生成 表由 esttab 出、图由命令出，禁止手工贴数
8 交付包归档 05_delivery 按批次归档，不删除

7.3 反 p-hacking：预注册检验清单

做法：在跑任何稳健性之前，先在飞书文档写一份《稳健性检验预注册清单》，列明要做的检验、判定标准、以及”若不一致将如何解释”。执行时严格按清单委派。

三个收益

  • 技术上：清单即批次模板，直接转成任务表

  • 学术上：具备预注册痕迹，抗审稿质疑

  • 心理上：防止”跑着跑着开始找显著”

清单模板字段：检验编号｜质疑维度｜检验设计｜预期方向｜判定标准｜若不一致的处理方式

7.4 数据安全与合规

风险 处置
原始微观数据外泄 StataMCP 本地/内网部署；数据不出域
个体隐私字段 进 Stata 前脱敏；do 中不 print 明细
涉密/受限数据 独立机器、断网、禁止上传云盘
云盘权限过宽 按 6.6 矩阵设置；外部合作者限定批次
提示词泄露数据 Prompt 里只写路径与字段名，不贴数据行

一句话原则：指令可以出域，数据不出域；结果可以上云，原始不上云。

7.5 平台能力边界与预案

边界 表现 预案
批次锁 上一批未交付不能开新批 提前规划批次；或用多对话分区（S2）
并发资源上限 任务太多排队 单批 ≤ 20 个；置换类再分子批
MCP 服务单点 服务挂了全部停 关键批次前做 L1–L5 验证；保留 batch 回退路径
长任务超时 置换/自助超时 降重复次数、拆批、提高超时
模型理解偏差 生成的设定与意图不符 Prompt 六要素 + 执行后必查 log 首行设定

8.2 综合实战任务书

题目：任选一个公开政策冲击（环保督察、高铁开通、自贸区设立、低碳城市试点等），使用地级市面板，完成一套可提交评审的实证交付包。

必做项

  1. 识别策略说明（1 页，含处理定义、对照逻辑、样本规则）

  2. 基准 DID（含聚类，报 N 与组别样本量）

  3. 事件研究（基期明确、端点合并规则写明）

  4. 预注册稳健性清单（≥ 8 项）

  5. 一次并行委派执行（≥ 8 子任务）

  6. 汇总矩阵 + 置换分布图或异质性热力图（二选一）

  7. 飞书多维表格台账（每任务一行，含 do/log/图链接）

  8. 诊断报告（含”结论稳定性判定”与”反转项处理说明”）

  9. ENV.md + batch_manifest.json

选做项（加分）

  • 多估计量 DID 对照表（csdid/drdid/did_imputation）

  • 合成控制对照

  • DML 稳健性

  • 空间权重矩阵敏感性

8.3 评分 Rubric

维度 权重 优秀（90+） 合格（75–89） 不合格（<75）
识别设计 20% 处理定义清晰、对照逻辑站得住、有反事实讨论 基本成立，个别环节含糊 处理/对照混淆
执行完整性 20% 批次全交付、无静默失败、目录规范 有 1–2 项缺失但已说明 大量缺失且无说明
校验严谨性 20% 12 项自检全打勾、反转项如实报告并解释 少数项缺失 只报显著、隐藏反转
可复现性 20% master.do 可一键跑通、ANOM 版本齐全、哈希登记 部分可复现 换机跑不通
协同治理 15% 台账字段完整、版本规范、评审痕迹清晰 台账可用 无台账或手填数据
前沿应用 5% 有方法对照或敏感性曲线 有 1 项拓展 无

术语 含义
MCP Model Context Protocol，模型调用外部工具的标准化协议
